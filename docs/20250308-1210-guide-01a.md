## Executive Summary

This document describes the complete architecture for the Pyvider Cty module, a Python implementation of Terraform's type system designed to enable the development of Terraform providers in Python. The system implements a comprehensive type system that closely mirrors Go's `go-cty` while leveraging Python's type system advantages.

The architecture follows these core principles:
- Maintain clear separation between types, values, and schema
- Embrace Pythonic patterns while ensuring compatibility with Terraform
- Provide a clean, intuitive developer experience
- Enable robust testing against actual Terraform behavior

This document outlines the full architecture, including implementation strategies, design decisions, and component interactions.

## System Architecture

### Overall Design

Pyvider Cty is designed as a standalone module that provides the complete type system functionality needed for Terraform providers written in Python. It serves as the foundation for schema definition and value handling throughout the Pyvider ecosystem.

### Key Components

The system is built around these core components:

1. **Type System**: Defines the structure and validation rules for values
2. **Value System**: Represents immutable, typed values with support for unknowns
3. **Serialization System**: Handles encoding/decoding to various formats
4. **Conversion System**: Manages conversion between different types
5. **Path System**: Represents paths to values within nested structures

- **Path** provides navigation through nested **Values**

## Core Type System

### Base Type Interface

The foundation of the type system is the abstract `Type` class:

```python
from abc import ABC, abstractmethod
from typing import Any, Generic, TypeVar, cast

T = TypeVar("T")

class Type(ABC, Generic[T]):
    """Base class for all Cty types."""
    
    @abstractmethod
    def validate(self, value: Any) -> T:
        """Validate and coerce the value to this type."""
        pass

    @abstractmethod
    def equal(self, other: "Type") -> bool:
        """Check equality between this type and another."""
        pass

    @abstractmethod
    def usable_as(self, other: "Type") -> bool:
        """Determine if this type can be used as another."""
        pass
```

Internally, each type is implemented as a class prefixed with `Cty` (e.g., `CtyString`), but these are exported without the prefix for a clean public API.

### Type Hierarchy

![Type Hierarchy](architecture-diagram-3.png)

The type system follows this hierarchy:

1. **Primitive Types**
   - `String`: Represents text values
   - `Number`: Represents numeric values (both integer and floating-point)
   - `Bool`: Represents boolean values

2. **Collection Types**
   - `List`: Ordered sequence of values of the same type
   - `Map`: Key-value mapping with string keys and same-type values
   - `Set`: Unordered collection of unique values of the same type

3. **Structural Types**
   - `Object`: Collection of named attributes with potentially different types
   - `Tuple`: Fixed-length sequence with potentially different types per position
   - `Dynamic`: Special type that can represent any other type

### Type Implementation Strategy

Each type class follows this implementation pattern:

```python
# Type module implementation (primitives/string.py)
class CtyString(Type[str]):
    """String type for Terraform values."""
    
    def validate(self, value: Any) -> str:
        """Validate value as string or mark as unknown."""
        if isinstance(value, UnknownValue):
            return value
            
        if value is None:
            return None
            
        if not isinstance(value, str):
            raise TypeError(f"Expected string, got {type(value).__name__}")
        return value
    
    def equal(self, other: Type) -> bool:
        """Check equality with another type."""
        return isinstance(other, CtyString)
        
    def usable_as(self, other: Type) -> bool:
        """Check if this type can be used as another type."""
        return isinstance(other, CtyString)
```

Collection and structural types also store their element or attribute types and validate recursively:

```python
class CtyList(Type[list[T]]):
    """List type for ordered sequences of same-typed values."""
    
    def __init__(self, element_type: Type[T]):
        self.element_type = element_type
        
    def validate(self, value: Any) -> list[T]:
        if isinstance(value, UnknownValue):
            return value
            
        if value is None:
            return None
            
        if not isinstance(value, (list, tuple)):
            raise TypeError(f"Expected list, got {type(value).__name__}")
            
        return [self.element_type.validate(item) for item in value]
        
    def equal(self, other: Type) -> bool:
        if not isinstance(other, CtyList):
            return False
        return self.element_type.equal(other.element_type)
```

## Value System

### Value Representation

The core of the value system is the `Value` class, which wraps a raw value with its type:

```python
class Value:
    """Immutable representation of a Terraform-compatible value with type information."""
    
    def __init__(self, raw_value: Any, type_def: Type):
        self._raw_value = raw_value
        self._type = type_def
        
    @property
    def type(self) -> Type:
        """The type of this value."""
        return self._type
        
    @property
    def raw_value(self) -> Any:
        """The raw Python value."""
        return self._raw_value
        
    def is_known(self) -> bool:
        """Whether this value is known (not unknown)."""
        return not isinstance(self._raw_value, UnknownValue)
        
    def is_null(self) -> bool:
        """Whether this value is null."""
        return self._raw_value is None
```

### Unknown and Null Values

Special value types are provided for representing unknown and null values:

```python
class UnknownValue:
    """Represents an unknown value in Terraform."""
    pass

def UnknownVal(type_def: Type) -> Value:
    """Create an unknown value of the specified type."""
    return Value(UnknownValue(), type_def)
    
def NullVal(type_def: Type) -> Value:
    """Create a null value of the specified type."""
    return Value(None, type_def)
```

Unknown values also support refinements to constrain what they might be:

```python
class RefinementBuilder:
    """Builder for refining unknown values with constraints."""
    
    def __init__(self, value: Value):
        self.value = value
        self.constraints = []
        
    def not_null(self) -> 'RefinementBuilder':
        """Mark that this unknown value cannot be null."""
        self.constraints.append(lambda v: v is not None)
        return self
        
    def string_prefix(self, prefix: str) -> 'RefinementBuilder':
        """Specify that this unknown string value has a known prefix."""
        self.constraints.append(lambda v: isinstance(v, str) and v.startswith(prefix))
        return self
        
    def build(self) -> Value:
        """Build the refined value."""
        # Refinements are stored with the value
        refined_value = UnknownRefinedValue(self.constraints)
        return Value(refined_value, self.value.type)
```

### Value Operations

Values provide operations that respect their types and handle unknown propagation:

```python
class Value:
    # ... (previous methods)
    
    def get_attr(self, name: str) -> 'Value':
        """Get an attribute from an object value."""
        if not self.is_known():
            # Unknown values propagate through attribute access
            return UnknownVal(self.type.get_attribute_type(name))
            
        if not isinstance(self.type, CtyObject):
            raise TypeError(f"Cannot get attribute from non-object value")
            
        attr_type = self.type.get_attribute_type(name)
        attr_value = self.raw_value.get(name)
        
        return Value(attr_value, attr_type)
        
    def index(self, key: 'Value') -> 'Value':
        """Index into a collection value."""
        # Similar implementation that handles unknowns and type checking
```

Mathematical and logical operations are also implemented:

```python
class Value:
    # ... (previous methods)
    
    def add(self, other: 'Value') -> 'Value':
        """Add two values."""
        # Handle unknowns
        if not self.is_known() or not other.is_known():
            return UnknownVal(self.type)
            
        # Type checking
        if not isinstance(self.type, CtyNumber) or not isinstance(other.type, CtyNumber):
            raise TypeError("Cannot add non-number values")
            
        # Actual operation
        result = self.raw_value + other.raw_value
        return Value(result, self.type)
```

### Value Path System

The path system allows referencing parts of nested values:

```python
class Path:
    """Represents a path to a value within a nested structure."""
    
    @staticmethod
    def root() -> 'Path':
        """Create a root path."""
        return Path([])
        
    def __init__(self, steps: list['PathStep']):
        self.steps = steps
        
    def get_attr(self, name: str) -> 'Path':
        """Add an attribute access step to this path."""
        return Path(self.steps + [GetAttrStep(name)])
        
    def index(self, key: Value) -> 'Path':
        """Add an index access step to this path."""
        return Path(self.steps + [IndexStep(key)])
        
    def apply(self, value: Value) -> Value:
        """Apply this path to a value to extract a nested value."""
        result = value
        for step in self.steps:
            result = step.apply(result)
        return result
```

Path steps are implemented as:

```python
class PathStep(ABC):
    """Abstract base class for path steps."""
    
    @abstractmethod
    def apply(self, value: Value) -> Value:
        """Apply this step to a value."""
        pass
        
class GetAttrStep(PathStep):
    """Step that accesses an attribute of an object."""
    
    def __init__(self, name: str):
        self.name = name
        
    def apply(self, value: Value) -> Value:
        return value.get_attr(self.name)
        
class IndexStep(PathStep):
    """Step that indexes into a collection."""
    
    def __init__(self, key: Value):
        self.key = key
        
    def apply(self, value: Value) -> Value:
        return value.index(self.key)
```

## Serialization Architecture

### JSON Encoding/Decoding

The JSON encoding system converts between `Value` objects and JSON:

```python
class JSONEncoder:
    """Encodes Cty values to JSON."""
    
    @staticmethod
    def encode(value: Value) -> bytes:
        """Encode a value to JSON bytes."""
        if not value.is_known():
            # Special marker for unknown values
            return b'"__UNKNOWN__"'
            
        if value.is_null():
            return b'null'
            
        # Handle different types
        if isinstance(value.type, CtyString):
            return json.dumps(value.raw_value).encode('utf-8')
        elif isinstance(value.type, CtyNumber):
            return json.dumps(value.raw_value).encode('utf-8')
        elif isinstance(value.type, CtyBool):
            return json.dumps(value.raw_value).encode('utf-8')
        elif isinstance(value.type, CtyList):
            items = [JSONEncoder.encode(v).decode('utf-8') for v in value.as_value_slice()]
            return f"[{','.join(items)}]".encode('utf-8')
        # Handle other types...
```

And decoding:

```python
class JSONDecoder:
    """Decodes JSON to Cty values."""
    
    @staticmethod
    def decode(data: bytes, type_def: Type) -> Value:
        """Decode JSON bytes to a value."""
        # Handle special markers
        if data == b'"__UNKNOWN__"':
            return UnknownVal(type_def)
            
        if data == b'null':
            return NullVal(type_def)
            
        # Parse JSON
        raw_value = json.loads(data.decode('utf-8'))
        
        # Validate against type
        return Value(type_def.validate(raw_value), type_def)
```

### DynamicValue Integration

The `DynamicValue` handler integrates with Terraform's protobuf messages:

```python
class DynamicValueHandler:
    """Handles conversion between Python values and Terraform DynamicValue."""
    
    @staticmethod
    def encode(value: Value) -> DynamicValue:
        """Convert a Value to a DynamicValue protobuf message."""
        if not value.is_known():
            # Handle unknown values specially
            return DynamicValue(unknown=True)
            
        # For known values, use JSON encoding
        json_data = JSONEncoder.encode(value)
        return DynamicValue(json=json_data)
            
    @staticmethod
    def decode(dynamic_value: DynamicValue, expected_type: Type) -> Value:
        """Convert a DynamicValue protobuf message to a Value."""
        if dynamic_value.unknown:
            return UnknownVal(expected_type)
            
        if dynamic_value.json:
            return JSONDecoder.decode(dynamic_value.json, expected_type)
            
        if dynamic_value.msgpack:
            return MsgpackDecoder.decode(dynamic_value.msgpack, expected_type)
```

### Serialization Flow

![Serialization Architecture](architecture-diagram-4.png)

The serialization system follows these flows:

1. **Value to JSON/Msgpack**:
   - Value → Raw Data → JSON/Msgpack Bytes

2. **JSON/Msgpack to Value**:
   - JSON/Msgpack Bytes → Raw Data → Validation → Value

3. **Value to DynamicValue**:
   - Value → JSON/Msgpack Bytes → DynamicValue (protobuf)

4. **DynamicValue to Value**:
   - DynamicValue (protobuf) → JSON/Msgpack Bytes → Value

## Type Conversion System

### Conversion Rules

The conversion system handles transformations between compatible types:

```python
def convert(value: Value, target_type: Type, safe: bool = True) -> Value:
    """Convert a value to the target type."""
    if value.type.equal(target_type):
        return value
        
    # Handle unknowns
    if not value.is_known():
        return UnknownVal(target_type)
        
    # Handle nulls
    if value.is_null():
        return NullVal(target_type)
        
    # Handle specific conversions
    if isinstance(value.type, CtyString) and isinstance(target_type, CtyNumber):
        try:
            numeric_value = float(value.raw_value)
            return Value(numeric_value, target_type)
        except ValueError:
            if safe:
                raise TypeError(f"Cannot convert {value} to {target_type}")
            return UnknownVal(target_type)
    
    # More conversion rules...
```

### Safe vs Unsafe Conversions

The conversion system supports both safe and unsafe conversions:

- **Safe Conversions**: Fail with an error if the conversion isn't possible
- **Unsafe Conversions**: Return an unknown value if the conversion isn't possible

```python
# Safe conversion (raises error if impossible)
result = convert(string_value, Number(), safe=True)

# Unsafe conversion (returns unknown if impossible)
result = convert(string_value, Number(), safe=False)
```

### Type Unification

The conversion system also supports unifying multiple values to a common type:

```python
def unify(values: list[Value], safe: bool = True) -> tuple[Type, list[Value]]:
    """Find a common type for multiple values and convert them."""
    if not values:
        raise ValueError("Cannot unify empty list of values")
        
    # Collect types
    types = [v.type for v in values]
    
    # Find most specific type that all can convert to
    target_type = find_common_type(types)
    if target_type is None:
        if safe:
            raise TypeError("No common type found for values")
        target_type = Dynamic()
        
    # Convert all values
    converted = [convert(v, target_type, safe=safe) for v in values]
    
    return target_type, converted
```

## Schema Integration

### Decorator Pattern Implementation

The schema system integrates with Cty using a decorator pattern:

```python
def resource(cls=None, *, name: Optional[str] = None):
    """Decorator for defining Terraform resource schemas."""
    def wrapper(cls):
        annotations = get_type_hints(cls)
        attributes = {}
        
        # Process field annotations and metadata
        for field_name, field_type in annotations.items():
            if field_name.startswith('_'):
                continue
                
            field_obj = getattr(cls, field_name, None)
            if not hasattr(field_obj, '_field_metadata'):
                raise ValueError(f"Field {field_name} missing metadata. Use the field() function.")
                
            metadata = field_obj._field_metadata
            
            # Store attribute configuration
            attributes[field_name] = {
                'type': field_type,
                'required': metadata.get('required', False),
                'computed': metadata.get('computed', False),
                'description': metadata.get('description', ''),
                # Additional metadata...
            }
        
        # Store schema info on the class
        cls._schema_name = name or cls.__name__.lower()
        cls._schema_attributes = attributes
        
        # Add schema methods
        cls.to_proto = schema_to_proto.__get__(cls)
        
        return cls
        
    if cls is None:
        return wrapper
    return wrapper(cls)
```

### Field Definition

Fields are defined using a factory function that creates descriptors:

```python
def field(*, required=False, computed=False, default=None, description=None, **kwargs):
    """Define a resource field with metadata."""
    metadata = {
        'required': required,
        'computed': computed,
        'description': description,
        'default': default,
        **kwargs
    }
    
    # Create a descriptor that will hold our metadata
    class FieldDescriptor:
        def __init__(self):
            self._field_metadata = metadata
            
        def __get__(self, obj, objtype=None):
            if obj is None:
                return self
            return obj.__dict__.get(self._name, default)
            
        def __set__(self, obj, value):
            obj.__dict__[self._name] = value
            
        def __set_name__(self, owner, name):
            self._name = name
    
    return FieldDescriptor()
```

### Schema-to-Protocol Conversion

The schema system converts annotated classes to Terraform protocol buffer schemas:

```python
def schema_to_proto(cls):
    """Convert schema to Protocol Buffer format."""
    from pyvider.protocols.tfprotov6.protobuf import Schema, StringKind
    
    attributes = []
    for name, attr_info in cls._schema_attributes.items():
        cty_type = attr_info['type']
        
        # Convert Cty type to protocol buffer type
        pb_type = _convert_type_to_schema_type(cty_type)
        
        attributes.append(
            Schema.Attribute(
                name=name,
                type=pb_type,
                description=attr_info.get('description', name),
                required=attr_info.get('required', False),
                computed=attr_info.get('computed', False),
                optional=attr_info.get('optional', False),
                sensitive=attr_info.get('sensitive', False),
                description_kind=StringKind.PLAIN
            )
        )
    
    return Schema(
        version=1,
        block=Schema.Block(
            attributes=attributes,
            description=cls.__doc__ or cls.__name__,
            description_kind=StringKind.PLAIN
        )
    )
```

   - Path representation
