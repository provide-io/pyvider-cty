## Introduction

`pyvider.cty` is a Python implementation of a type system inspired by Go's `cty` package (used by Terraform). It provides a robust, strongly-typed framework for defining, validating, and manipulating structured data with support for unknown values, null values, and type conversions.

### Purpose

The primary purposes of `pyvider.cty` are:

1. To provide a Pythonic implementation of Terraform's type system
2. To enable development of Terraform providers in Python
3. To handle complex data validation and transformation
4. To support serialization formats required by Terraform protocols

### Installation

```bash
pip install pyvider-cty
```

### Importing

**IMPORTANT**: Always import directly from the top-level package:

```python
from pyvider.cty import (
    CtyBool, CtyDynamic, CtyList, CtyMap, CtyNumber, 
    CtyObject, CtySet, CtyString, CtyTuple, CtyType, 
    CtyValue
)
```

Never import from submodules (e.g., `pyvider.cty.types.primitives`) as these internal paths may change.

## Core Concepts

`pyvider.cty` is built around two fundamental concepts: **types** and **values**.

### Types vs. Values

- **Type**: Represents a particular way of storing and manipulating data
- **Value**: Combination of data and a type that describes how to interpret that data

For example, `CtyString` is a type, while a specific string value like `"hello"` wrapped in a `CtyValue` is a value.

### Special Value States

`pyvider.cty` supports special value states:

- **Unknown Values**: Values that have a type but no known data yet
- **Null Values**: Values that explicitly represent the absence of data
- **Marked Values**: Values with additional metadata attached

### Value Operations

Each type defines operations that can be performed on its values. For example:
- Strings support concatenation
- Numbers support arithmetic operations
- Lists support indexing and concatenation

## Type System

`pyvider.cty` includes a comprehensive type system with three main categories:

### Primitive Types

```python
from pyvider.cty import CtyString, CtyNumber, CtyBool

# Creating primitive types
string_type = CtyString()
number_type = CtyNumber()
bool_type = CtyBool()

# Validating values against types
valid_string = string_type.validate("hello")
valid_number = number_type.validate(42)
valid_bool = bool_type.validate(True)
```

### Collection Types

```python
from pyvider.cty import CtyList, CtyMap, CtySet, CtyString, CtyNumber

# List of strings
string_list = CtyList(element_type=CtyString())

# Map with string keys and number values
number_map = CtyMap(key_type=CtyString(), value_type=CtyNumber())

# Set of strings
string_set = CtySet(element_type=CtyString())

# Validating collections
valid_list = string_list.validate(["a", "b", "c"])
valid_map = number_map.validate({"x": 1, "y": 2, "z": 3})
valid_set = string_set.validate({"a", "b", "c"})
```

### Structural Types

```python
from pyvider.cty import CtyObject, CtyTuple, CtyDynamic, CtyString, CtyNumber, CtyBool

# Object with named attributes
person_type = CtyObject(attribute_types={
    "name": CtyString(),
    "age": CtyNumber(),
    "is_active": CtyBool()
})

# Tuple with mixed types
coordinate_type = CtyTuple(types=(CtyNumber(), CtyNumber(), CtyString()))

# Dynamic type (can be any type)
dynamic_type = CtyDynamic()

# Validating structural types
valid_person = person_type.validate({
    "name": "Alice",
    "age": 30,
    "is_active": True
})

valid_coordinate = coordinate_type.validate((10.5, 20.3, "point_a"))
valid_dynamic = dynamic_type.validate("anything works")
```

### Type Relationships

Types support two key relationship checks:

1. **Equality** (`equal` method): Checks if two types are identical
2. **Usability** (`usable_as` method): Checks if one type can be used where another is expected

```python
# Type equality
string_list.equal(CtyList(element_type=CtyString()))  # True
string_list.equal(CtyList(element_type=CtyNumber()))  # False

# Type usability
full_person = CtyObject(attribute_types={
    "name": CtyString(),
    "age": CtyNumber(),
    "email": CtyString()
})

basic_person = CtyObject(attribute_types={
    "name": CtyString(),
    "age": CtyNumber()
})

# A full_person can be used where a basic_person is expected
full_person.usable_as(basic_person)  # True

# A basic_person cannot be used where a full_person is expected
basic_person.usable_as(full_person)  # False
```

## Working with Values

Values in `pyvider.cty` are always immutable and are represented by the `CtyValue` class.

### Creating Values

```python
from pyvider.cty import CtyValue, CtyString, CtyNumber, CtyBool, CtyList

# Create primitive values
string_val = CtyValue(CtyString(), "hello")
number_val = CtyValue(CtyNumber(), 42)
bool_val = CtyValue(CtyBool(), True)

# Create list value
list_val = CtyValue(CtyList(element_type=CtyString()), ["a", "b", "c"])

# Static factory methods
bool_true = CtyValue.bool(True)
unknown_string = CtyValue.unknown(CtyString())
null_number = CtyValue.null(CtyNumber())
```

### Value Properties

```python
# Check if a value is known
if number_val.is_unknown:
    print("Value is unknown")
else:
    print("Value is known:", number_val.value)

# Check if a value is null
if number_val.is_null:
    print("Value is null")
else:
    print("Value is not null:", number_val.value)

# Get the type of a value
value_type = string_val.type
print("Value type:", value_type.__class__.__name__)
```

### Value Operations

Operations on values are type-specific and implemented in the `operations.py` module.

```python
from pyvider.cty.operations import add, equals, length, get_attribute

# String concatenation
hello = CtyValue(CtyString(), "Hello, ")
world = CtyValue(CtyString(), "world!")
greeting = add(hello, world)  # "Hello, world!"

# Number addition
five = CtyValue(CtyNumber(), 5)
three = CtyValue(CtyNumber(), 3)
eight = add(five, three)  # 8

# Value equality
are_equal = equals(five, CtyValue(CtyNumber(), 5))  # True

# Collection length
list_len = length(list_val)  # 3

# Object attribute access
person = CtyValue(person_type, {
    "name": "Alice",
    "age": 30,
    "is_active": True
})
name = get_attribute(person, "name")  # "Alice"
```

### Marks

Values can be marked with additional metadata:

```python
# Add a mark to a value
marked_value = string_val.mark("sensitive")

# Check if a value has a mark
is_sensitive = marked_value.has_mark("sensitive")  # True

# Remove marks from a value
unmarked_value, marks = marked_value.unmark()
```

### Refinements

Refinements provide additional constraints for unknown values:

```python
from pyvider.cty.values.refinement import ValueRefinementBuilder

# Create an unknown string value
unknown_url = CtyValue.unknown(CtyString())

# Add refinements
refined_url = (
    ValueRefinementBuilder(unknown_url)
    .not_null()
    .string_prefix("https://")
    .new_value()
)
```

## Serialization and Encoding

`pyvider.cty` supports multiple serialization formats for interoperability with Terraform and other systems.

### JSON Serialization

```python
from pyvider.cty.encoding.json_serializer_serializer import JsonSerializer

# Create a serializer
json_serializer = JsonSerializer()

# Serialize a value to JSON
json_bytes = json_serializer.serialize(person)

# Deserialize from JSON
deserialized = json_serializer.deserialize(json_bytes)

# Type-aware deserialization
typed_deserialized = json_serializer.deserialize_with_type(
    json_bytes, person_type
)
```

### MessagePack Serialization

```python
from pyvider.cty.encoding.msgpack import marshal, unmarshal

# Serialize to MessagePack
msgpack_bytes = await marshal(person)

# Deserialize from MessagePack
deserialized = await unmarshal(msgpack_bytes)
```

## Path-based Navigation

`pyvider.cty` provides a path system for navigating through nested values, similar to JavaScript property access.

### Creating Paths

```python
from pyvider.cty.path import Path

# Create paths
empty_path = Path.empty()
name_path = Path.get_attr("name")
first_item = Path.index(0)
map_key = Path.key("field1")
```

### Chaining Paths

```python
# Build complex paths
address_city = Path.get_attr("address").child("city")
user_first_tag = Path.get_attr("user").child("tags").index_step(0)
```

### Applying Paths

```python
# Apply a path to a value
user_value = ...  # A complex user object
username = await name_path.apply_path(user_value)
```

### Path String Representation

```python
# Convert paths to strings
path_str = address_city.string()  # ".address.city"
```

## Type Conversion

`pyvider.cty` supports both safe and unsafe conversions between types.

### Safe Conversions

Safe conversions guarantee no data loss:

```python
from pyvider.cty.convert import convert

# Number to string conversion (safe)
num_val = CtyValue(CtyNumber(), 42)
str_val = await convert(num_val, CtyString())  # "42"
```

### Unsafe Conversions

Unsafe conversions may lose information:

```python
from pyvider.cty.convert import convert_unsafe

# String to number conversion (unsafe)
str_val = CtyValue(CtyString(), "42")
num_val = await convert_unsafe(str_val, CtyNumber())  # 42

# This could lose information:
str_val = CtyValue(CtyString(), "42.5")
num_val = await convert_unsafe(str_val, CtyNumber())  # 42.5
```

### Conversion Checks

```python
from pyvider.cty.convert import can_convert, can_convert_unsafe

# Check if conversion is possible
is_convertible = await can_convert(str_val.type, CtyNumber())  # False
is_unsafe_convertible = await can_convert_unsafe(str_val.type, CtyNumber())  # True
```

### Type Unification

```python
from pyvider.cty.convert import unify, unify_unsafe

# Find a common type for multiple values
values = [
    CtyValue(CtyString(), "hello"),
    CtyValue(CtyString(), "world")
]

unified_type, conversions = await unify([v.type for v in values])
# unified_type will be CtyString
```

## Integration with Terraform

`pyvider.cty` is designed to integrate with Terraform's plugin system.

### Schema Definition

```python
from pyvider.cty import CtyString, CtyNumber, CtyBool, CtyList
from pyvider.schema import resource, field

@resource(name="example_resource")
class ExampleResource:
    """Example Terraform resource."""
    
    name: CtyString = field(
        required=True,
        description="Resource name"
    )
    
    count: CtyNumber = field(
        default=1,
        description="Number of resources to create"
    )
    
    enabled: CtyBool = field(
        default=True,
        description="Whether the resource is enabled"
    )
    
    tags: CtyList[CtyString] = field(
        optional=True,
        description="Resource tags"
    )
```

### Protocol Buffer Conversion

```python
# Convert schema to Protocol Buffer
schema_pb = ExampleResource.to_proto()
```

## Best Practices

### Type Definition

1. **Define types once and reuse them**: Create constants for commonly used types
2. **Be specific with types**: Use the most specific type that applies
3. **Document complex types**: Add docstrings explaining type structure

```python
# Good practice: Define types as constants
STRING_TYPE = CtyString()
NUMBER_TYPE = CtyNumber()
BOOL_TYPE = CtyBool()

# Good practice: Define complex types with clear names
SERVER_CONFIG_TYPE = CtyObject(attribute_types={
    "hostname": STRING_TYPE,
    "port": NUMBER_TYPE,
    "ssl_enabled": BOOL_TYPE,
    "tags": CtyList(element_type=STRING_TYPE)
})
```

### Value Handling

1. **Always check for unknown and null values**: Handle special states explicitly
2. **Use immutability to your advantage**: Create modified copies rather than mutating
3. **Propagate marks correctly**: Preserve marks when transforming values

```python
# Good practice: Check for special states
def process_config(config):
    if config.is_unknown:
        return "Configuration contains unknown values"
        
    if config.is_null:
        return "Configuration is null"
        
    # Process the known, non-null value
    hostname = config.get_attr("hostname").value
    return f"Processing server: {hostname}"
```

### Error Handling

1. **Use specific exceptions**: Catch and handle the specific exception types
2. **Provide context in error messages**: Include details about what failed
3. **Validate early**: Check values before performing operations

```python
# Good practice: Specific exception handling
from pyvider.cty.exceptions import CtyValidationError, TypeMismatchError

try:
    validated = server_type.validate(server_data)
except CtyValidationError as e:
    print(f"Validation failed: {e}")
except TypeMismatchError as e:
    print(f"Type mismatch: {e}")
```

## API Reference

### Types

#### Base Type
- `CtyType`: Abstract base class for all types

#### Primitive Types
- `CtyString`: String type
- `CtyNumber`: Number type
- `CtyBool`: Boolean type

#### Collection Types
- `CtyList`: List type with elements of a specific type
- `CtyMap`: Map type with string keys and values of a specific type
- `CtySet`: Set type with elements of a specific type

#### Structural Types
- `CtyObject`: Object type with named attributes of various types
- `CtyTuple`: Tuple type with fixed-position elements of various types
- `CtyDynamic`: Dynamic type that can represent any value

### Values

- `CtyValue`: Represents a value with a specific type
  - Properties:
    - `type`: The type of this value
    - `value`: The raw value
    - `is_unknown`: Whether the value is unknown
    - `is_null`: Whether the value is null
  - Methods:
    - `has_mark(mark)`: Check if the value has a specific mark
    - `mark(mark)`: Add a mark to the value
    - `unmark()`: Remove all marks from the value
    - `refine()`: Create a refinement builder for this value

### Operations

- `equals(a, b)`: Check if two values are equal
- `add(a, b)`: Add two values
- `subtract(a, b)`: Subtract one value from another
- `multiply(a, b)`: Multiply two values
- `divide(a, b)`: Divide one value by another
- `modulo(a, b)`: Calculate the modulo of one value by another
- `negate(a)`: Negate a value
- `get_attribute(obj, name)`: Get an attribute from an object
- `get_element(collection, index)`: Get an element from a collection
- `length(collection)`: Get the length of a collection
- `contains(collection, item)`: Check if a collection contains an item
- `concat_lists(*lists)`: Concatenate multiple lists
- `merge_maps(*maps)`: Merge multiple maps
- `slice_string(str_val, start_idx, end_idx)`: Extract a substring
- `slice_list(list_val, start_idx, end_idx)`: Extract a slice from a list

### Path Navigation

- `Path`: Path for navigating through nested values
  - Factory methods:
    - `empty()`: Create an empty path
    - `get_attr(name)`: Create a path to an attribute
    - `index(idx)`: Create a path to an indexed element
    - `key(key)`: Create a path to a map key
  - Methods:
    - `child(name)`: Append an attribute step
    - `index_step(idx)`: Append an index step
    - `key_step(key)`: Append a key step
    - `apply_path(value)`: Apply this path to a value
    - `apply_path_type(type_)`: Apply this path to a type
    - `string()`: Get a string representation of this path

### Conversion

- `convert(value, target_type)`: Safely convert a value to a target type
- `convert_unsafe(value, target_type)`: Convert a value to a target type, allowing unsafe conversions
- `can_convert(source_type, target_type)`: Check if a safe conversion is possible
- `can_convert_unsafe(source_type, target_type)`: Check if any conversion is possible
- `unify(types)`: Find a common type for multiple types
- `unify_unsafe(types)`: Find a common type, allowing unsafe conversions
