### **Abstracting Common Logic in Terraform Plugin Handlers**
Since **each handler in `tfprotov6/` has logic that will be reused**, the goal is to **abstract shared behaviors** while keeping the handlers clean and maintainable.

---

## **📌 What Can Be Reused Across Handlers?**
Each Terraform plugin handler (**GetProviderSchema**, **ApplyResourceChange**, etc.) likely performs **similar low-level operations**:

### **1️⃣ Common gRPC Request Handling**
- **Extracting request data**  
- **Error handling** (returning proper Terraform diagnostics)  
- **Logging/debugging behavior**  

#### **Example (Before Refactoring)**
```python
async def GetProviderSchema(self, request, context):
    try:
        schema = self._provider.get_schema()
        return pb.GetProviderSchema.Response(schema=schema)
    except Exception as e:
        return pb.GetProviderSchema.Response(
            diagnostics=[pb.Diagnostic(severity=pb.Diagnostic.ERROR, summary="Schema error", detail=str(e))]
        )
```

#### **After Refactoring** (Move to `BaseHandler`)
```python
class BaseHandler:
    """Base class for Terraform handlers with common logic."""

    async def handle_request(self, request, context, handler_fn):
        """Generic request handler with logging and error handling."""
        try:
            return await handler_fn(request)
        except Exception as e:
            return self._error_response(e)

    def _error_response(self, error):
        """Generate a Terraform diagnostic error response."""
        return pb.Diagnostic(severity=pb.Diagnostic.ERROR, summary="Handler error", detail=str(error))
```
Then in your **actual handlers**, just call `handle_request`:

```python
class GetProviderSchemaHandler(BaseHandler):
    async def __call__(self, request, context):
        return await self.handle_request(request, context, self._process)

    async def _process(self, request):
        return pb.GetProviderSchema.Response(schema=self._provider.get_schema())
```
✅ **This removes duplicate error handling and keeps handlers focused on business logic.**

### **2️⃣ Shared Serialization / Deserialization**
Terraform gRPC messages require **structured encoding/decoding**, especially for `DynamicValue`.

💡 **Move serialization into a `DynamicValueHandler` utility.**

#### **Before (Manual Handling in Each Handler)**
```python
import json

async def ApplyResourceChange(self, request, context):
    try:
        raw_data = json.loads(request.plan.json)
        ...
    except Exception as e:
        ...
```

#### **After (Centralized in a Utility)**
```python
class DynamicValueHandler:
    """Helper class for encoding and decoding Terraform DynamicValues."""

    @staticmethod
    def decode(value):
        if value.json:
            return json.loads(value.json.decode('utf-8'))
        elif value.msgpack:
            return msgpack.unpackb(value.msgpack)
        return None

    @staticmethod
    def encode(value):
        return pb.DynamicValue(json=json.dumps(value).encode('utf-8'))
```
Now handlers can **just call**:

```python
raw_data = DynamicValueHandler.decode(request.plan)
```
✅ **This ensures consistent encoding across all handlers.**

### **3️⃣ Centralized Terraform Response Building**
Every handler returns a **Terraform gRPC response**, which follows a **fixed structure**.

💡 **Move response construction into a `TerraformResponseBuilder` helper.**

#### **Before (Duplicate Code in Each Handler)**
```python
async def ApplyResourceChange(self, request, context):
    try:
        result = self._apply_logic(request)
        return pb.ApplyResourceChange.Response(new_state=result)
    except Exception as e:
        return pb.ApplyResourceChange.Response(
            diagnostics=[pb.Diagnostic(severity=pb.Diagnostic.ERROR, summary="Apply error", detail=str(e))]
        )
```

#### **After (Centralized Helper)**
```python
class TerraformResponseBuilder:
    """Helper to construct Terraform plugin responses."""

    @staticmethod
    def success(response_type, **kwargs):
        return response_type(**kwargs)

    @staticmethod
    def error(response_type, error):
        return response_type(
            diagnostics=[pb.Diagnostic(severity=pb.Diagnostic.ERROR, summary="Error", detail=str(error))]
        )
```
Now, handlers can just call:
```python
return TerraformResponseBuilder.success(pb.ApplyResourceChange.Response, new_state=result)
```
✅ **This standardizes response handling across all handlers.**

### **📌 Final Refactored Layout**
Instead of every handler re-implementing **logging, error handling, serialization, and response building**, your **Terraform handlers** should use reusable base classes and utilities.

```
pyvider-tfprotov6/
│── handlers/
│   ├── base_handler.py            # Common request handling logic
│   ├── dynamic_value_handler.py   # Encoding/decoding logic
│   ├── response_builder.py        # Terraform response handling
│   ├── get_provider_schema.py     # Specific handler (inherits from base)
│   ├── apply_resource_change.py   # Specific handler (inherits from base)
│   ├── ...
```

## **🚀 Summary: How to Abstract Terraform Handlers Elegantly**
✅ **Move common logic to `BaseHandler`**
- Centralizes request handling
- Removes duplicate error handling

✅ **Extract `DynamicValueHandler`**
- Standardizes Terraform JSON/msgpack encoding/decoding

✅ **Use `TerraformResponseBuilder`**
- Makes response generation uniform across handlers

✅ **Keep handlers focused on business logic**
- Handlers should **only** contain Terraform-specific logic, not generic error handling, logging, or serialization.
