# Feature Matrix: `go-cty` vs. `pyvider.cty`

This document outlines a comparison of features between the reference `go-cty` implementation and `pyvider.cty`.

| Feature Category          | Feature                                  | `go-cty` Support                       | `pyvider.cty` Support                               | Notes / To Verify (for `pyvider.cty`)                 |
|---------------------------|------------------------------------------|----------------------------------------|-----------------------------------------------------|-------------------------------------------------------|
| **Core Types**            | String                                   | Yes (`cty.String`)                     | Yes (`CtyString`)                                   | Fully implemented.                                    |
|                           | Number (Arbitrary Precision)             | Yes (`cty.Number`, uses `*big.Float`)  | Yes (`CtyNumber`, uses `decimal.Decimal`)           | Appears fully implemented. Precision handling aligns. |
|                           | Bool                                     | Yes (`cty.Bool`)                       | Yes (`CtyBool`)                                     | Fully implemented.                                    |
|                           | List                                     | Yes (`cty.List(Type)`)                 | Yes (`CtyList(element_type: CtyType)`)              | Homogeneous elements enforced.                        |
|                           | Map (String Keys)                        | Yes (`cty.Map(Type)`)                  | Yes (`CtyMap(key_type: CtyString, value_type: CtyType)`) | String keys enforced by `CtyMap` definition.        |
|                           | Set                                      | Yes (`cty.Set(Type)`)                  | Yes (`CtySet(element_type: CtyType)`)               | Homogeneous elements enforced.                        |
|                           | Object                                   | Yes (`cty.Object(map[string]Type)`)    | Yes (`CtyObject(attribute_types: dict, optional_attributes: set)`) | Attribute definition, optional attributes supported.  |
|                           | Tuple                                    | Yes (`cty.Tuple([]Type)`)              | Yes (`CtyTuple(element_types: tuple)`)              | Fixed length, potentially heterogeneous elements.     |
|                           | Dynamic/Any                              | Yes (`cty.DynamicPseudoType`)          | Yes (`CtyDynamic`)                                  | Present. Behavior in operations and validation needs thorough testing. |
|                           | Capsule                                  | Yes (`cty.Capsule(name, GoType)`)      | No                                                  | Likely Not Applicable for a pure Python implementation. |
|                           | Function                                 | Yes (`cty.Function`)                   | No                                                  | Likely Not Applicable or a future consideration.      |
| **Special Values**        | Null                                     | Yes (Typed Null: `cty.NullVal(Type)`)  | Yes (`CtyValue.null(CtyType)`)                      | Correctly typed nulls.                                |
|                           | Unknown                                  | Yes (Typed Unknown: `cty.UnknownVal(Type)`) | Yes (`CtyValue.unknown(CtyType)`)                 | Correctly typed unknowns. Propagation in paths seen.  |
| **Value Representation**  | Immutability                             | Yes (Values are immutable)             | Yes (`CtyValue` is a frozen `attrs` class)        | Core design principle matches.                        |
|                           | Marks                                    | Yes                                    | Yes (`_marks` in `CtyValue`, `mark()`, `unmark()`) | Functionality appears equivalent.                   |
| **Basic Operations**      | Equality (Value)                         | `Value.Equals(Value) Value` (Bool)     | `CtyValue.__eq__(self, other)`                      | `__eq__` compares type, state, marks, and deep value. Returns `bool`. |
|                           | Type Access                              | `Value.Type() Type`                    | `CtyValue.type` property                            | Direct equivalent.                                    |
|                           | Raw Value Access (Capsule specific)      | `Value.RawValue() interface{}`         | Not directly applicable (no Capsule type)           | `CtyValue.value` gives Python value, raises for unknown. |
| **Type Operations**       | Equality (Type)                          | `Type.Equals(Type) bool`               | `CtyType.equal(CtyType) bool`                     | Implemented in base and specific types.               |
|                           | Compatibility Check                      | `Type.IsAssignableFrom(other Type) bool` | `CtyType.usable_as(other CtyType) bool`           | `usable_as` seems to be the equivalent of `go-cty`'s `Target.IsAssignableFrom(Source)`. |
| **Collection Operations** | Length                                   | `Value.Length() Value` (Number)        | `CtyValue.__len__() int`                            | `pyvider.cty` returns direct `int`. `go-cty` returns `cty.NumberVal`. |
|                           | Index (List/Tuple)                       | `Value.Index(key Value) Value`         | `CtyValue.__getitem__(index_or_slice)`, `CtyValue.element_at(index)` | `__getitem__` handles int index and slices. `element_at` for single int. |
|                           | Key (Map)                                | `Value.Index(key Value) Value`         | `CtyValue.__getitem__(key)`, `CtyValue.get(key)`  | `__getitem__` validates key, `get` allows default.  |
|                           | Get Attribute (Object)                   | `Value.GetAttr(name string) Value`     | `CtyValue.__getitem__(name)`, `CtyObject.get_attribute(value, name)` | `__getitem__` for string attr name.                 |
|                           | Iteration (List/Tuple/Set)               | `Value.ElementIterator()`              | `CtyValue.__iter__()` (yields elements)           | Standard Python iteration.                            |
|                           | Iteration (Map)                          | `Value.ElementIterator()` (sorted by key) | `CtyMap.element_iterator()` (sorted by key)       | Yields (`CtyValue` key, `CtyValue` value).          |
|                           | Has Index/Key/Attr                       | `Value.HasIndex(key Value) Value` (Bool) | `CtyValue.__contains__(item)`                     | `__contains__` logic varies by type (key for map, attr for object, value for list/set). |
|                           | Set Index (List - builder)               | (Builder pattern for some ops)         | `CtyList.append()` (returns new `CtyList` type)   | `pyvider.cty` emphasizes immutability for `CtyType` instances. `CtyValue` is immutable. |
|                           | Set Key (Map - builder)                  | (Builder pattern for some ops)         | `CtyValue.set(key, value)` (returns new `CtyValue`) | `pyvider.cty` returns new immutable `CtyValue`.     |
| **Path Navigation**       | Path Expression                          | Yes (`cty.Path`)                       | Yes (`CtyPath` with `GetAttrStep`, `IndexStep`, `KeyStep`) | Modelled closely on `go-cty`.                     |
|                           | Apply Path to Value                      | `Path.Apply(Value) (Value, error)`     | `CtyPath.apply_path(CtyValue) CtyValue`           | Handles unknown propagation, errors on null.          |
|                           | Apply Path to Type                       | `Path.ApplyType(Type) (Type, error)`   | `CtyPath.apply_path_type(CtyType) CtyType`        | Determines resulting type.                            |
| **Numeric Operations**    | Add, Subtract, Multiply, Divide, Modulo  | Yes (e.g., `Value.Add(Value) Value`)  | To Verify                                         | Need to check `CtyValue` for overloaded operators or specific methods for `CtyNumber`. |
|                           | Negate (Unary Minus)                     | Yes (`Value.Negate() Value`)           | To Verify                                         |                                                       |
|                           | Comparison (GT, LT, GTE, LTE)            | Yes (e.g., `Value.LessThan(Value) Value`)| To Verify                                         | `__eq__` exists, others?                              |
| **Boolean Operations**    | And, Or, Not                             | Yes (e.g., `Value.LogicalNot() Value`) | To Verify                                         |                                                       |
| **Type Conversion**       | Explicit Conversion                      | `convert.Convert(Value, Type) (Value, error)` | Partial (`pyvider.cty.conversion`)              | `marshal/unmarshal` exists. General `convert` function to verify. |
|                           | JSON Serialization (Value)               | `ctyjson.SimpleJSONValue{}.Marshal(Value, Type)` | `marshal_json(CtyValue)` (uses `CtyValue.to_json_comparable_dict()`) | `pyvider.cty`'s `to_json_comparable_dict` is the basis. `go-cty`'s `ctyjson` has more complex handling for unknowns, etc. that `pyvider.cty` now aims to match in its `JSONComparableValue` structure. |
|                           | JSON Deserialization (Value)             | `ctyjson.Unmarshal(bytes, Type) (Value, error)` | `unmarshal_json(data, CtyType) CtyValue`          |                                                       |
|                           | JSON Serialization (Type)                | `ctyjson.MarshalType(Type) (bytes, error)` | `marshal_type(CtyType)`                           |                                                       |
|                           | JSON Deserialization (Type)              | `ctyjson.UnmarshalType(bytes) (Type, error)` | `unmarshal_type(data_dict) CtyType`               |                                                       |

This matrix is based on analysis up to 2025-05-30. The "To Verify" column indicates areas where deeper investigation or implementation in `pyvider.cty` might be needed to confirm full feature parity for implemented parts.
