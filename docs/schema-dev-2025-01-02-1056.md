# **Pyvider Schema Documentation Outline**

---

## **1. Introduction to Pyvider Schemas**
- **Purpose of Pyvider Schemas**  
- Overview of how schemas mirror Terraform’s provider model  
- Key Concepts:  
  - **Modularity** – Composable fragments  
  - **Extensibility** – Attribute-level validators  
  - **Dynamic Validation** – Meta schemas and runtime constraints  

---

## **2. Core Concepts**

### **2.1 Types (`cty`)**
- **Definition**: Types represent the fundamental data shapes (string, number, etc.).  
- **Purpose**: Enforce data types for schema attributes.  
- **Key Classes**:  
  - `TFString` – Represents a string  
  - `TFNumber` – Represents a number (float or int)  
  - `TFBool` – Boolean type  
  - `TFMap` – Key-value mappings  
  - `TFList` – Ordered collections  
  - `TFObject` – Complex, nested structures  

- **Code Example**:  
```python
from pyvider.cty import TFString, TFNumber

string_type = TFString()
number_type = TFNumber()
```

- **When to Use**:  
  - Primitive attribute definitions  
  - Complex nested object types  

---

### **2.2 Attributes (`tfattrs`)**
- **Definition**: Attributes wrap `cty` to form **schema fields** with metadata and validation.  
- **Purpose**: Define resource properties with attached metadata (required, sensitive, etc.).  
- **Key Functions**:  
  - `tfstr` – String attribute  
  - `tfnum` – Number attribute  
  - `tfobj` – Nested object attribute  
  - `tflist` – List of attributes  

- **Code Example**:  
```python
from pyvider.schema.attributes import tfstr

filename = tfstr(required=True, description="Path to the target file")
```

- **Metadata Parameters**:  
  - `required` – Marks attribute as mandatory  
  - `computed` – Value determined by the provider  
  - `sensitive` – Redacts the value in logs  
  - `validators` – Attaches constraints  

---

### **2.3 Validators and Meta Schema**
- **Definition**: Validators apply **runtime constraints** to attributes, modifying the meta schema.  
- **Purpose**: Enforce rules such as string length, regex patterns, or value ranges.  
- **Key Functions**:  
  - `min_length` – Minimum string length  
  - `max_length` – Maximum string length  
  - `pattern` – Regex matching  
- **Code Example**:  
```python
from pyvider.hub.validators import Validators

Validators.attach(filename.metadata, "pattern", r".*\.txt$")
```

- **How Validators Impact Meta Schema**:  
  - Validators **alter the meta schema** dynamically.  
  - Applied per attribute (not globally).  

---

## **3. Building Schema Fragments**

### **3.1 What are Schema Fragments?**
- **Definition**: Partial schema definitions that can be **reused and composed** into larger schemas.  
- **Purpose**: Encourage modularity by separating reusable logic.  

- **Example**:  
```python
@attrs.define
class NetworkSchema:
    vpc_id = tfstr(required=True)
    subnet_id = tfstr(required=True)
```

---

### **3.2 Combining Fragments into Component Schemas**
- **Definition**: A complete schema composed of multiple fragments.  
- **Purpose**: Construct full resource or provider schemas by nesting smaller fragments.  
- **Code Example**:  
```python
@attrs.define
class DatabaseSchema:
    db_name = tfstr(required=True)
    network = tfobj(NetworkSchema())
```

---

## **4. Meta Schema Explained**
- **Definition**:  
  - A **meta schema** defines **rules about how attributes behave**, rather than what attributes exist.  
  - Represents **validators and attribute metadata** (like min/max length, regex).  

- **Example (HCL Representation)**:  
```hcl
resource "file_content" "target" {
    content = "example"
    _content {
      min_length = 3
      max_length = 10
    }
}
```
- `_content` modifies the **meta schema** of `content` by adding length constraints.  

- **Python Equivalent**:  
```python
content = tfstr(required=True)
Validators.attach(content.metadata, "min_length", 3)
Validators.attach(content.metadata, "max_length", 10)
```

## **5. Defining Full Resource Schemas**

### **5.1 Creating a Resource Schema**
- **Definition**: A schema that defines the full configuration for a resource.  
- **Combines**:  
  - **Attributes** (using `tfattrs`)  
  - **Fragments** (via composition)  
  - **Validators** (modifying the meta schema)  

- **Example**:  
```python
@attrs.define
class FileContentSchema:
    file = tfstr(required=True, validators=["pattern"])
    content = tfstr(required=True, validators=["min_length", "max_length"])
```

---

### **5.2 Dynamic Schema Expansion (Post Initialization)**
- **Definition**: Some schemas evolve **at runtime** based on flags or conditions.  
- **Example**:  
```python
@attrs.define
class DynamicSchema:
    base = tfstr(required=True)

    def __attrs_post_init__(self):
        if feature_flag("advanced_logging"):
            self.__class__.logging = tfstr(required=False)
```
- **Outcome**: `logging` is added **dynamically** if the flag is set.

## **6. Advanced Concepts**

### **6.1 Schema Evolution and Versioning**
- **Definition**: Versioned schema fragments enable gradual evolution.  
- **Example**:  
```python
@attrs.define
class NetworkSchemaV1:
    vpc_id = tfstr(required=True)

@attrs.define
class NetworkSchemaV2(NetworkSchemaV1):
    cidr_block = tfstr(required=True)
```
- `NetworkSchemaV2` extends V1 with new attributes.  

---

### **6.2 Nested and Conditional Blocks**
- **Definition**: Attributes that accept lists, maps, or nested objects.  
- **Example**:  
```python
@attrs.define
class LoadBalancerSchema:
    rules = tflist(tfobj(NetworkSchema))
```
- `rules` accepts a **list of network configurations**.

## **7. Testing and Validation**

### **7.1 Testing Schema Constraints**
- **Definition**: Test attribute constraints with unit tests.  
- **Example**:  
```python
def test_file_pattern():
    with pytest.raises(ValidationError):
        filename.validate("invalid.json")
```

---

## **8. Best Practices**

- **Reuse Schema Fragments** – Avoid duplication by fragmenting reusable sections.  
- **Attach Validators Early** – Ensure constraints are attached **at schema definition time**.  
- **Version Schema Fragments** – Use versioning to handle evolving resource requirements.
