# Compatibility Testing Framework for pyvider.cty

This directory contains tools and test cases for ensuring `pyvider.cty` maintains compatibility with the reference `go-cty` implementation.

## Overview

The testing strategy is data-driven and involves the following components:

1.  **Test Case Definitions (YAML):**
    *   Located in the `tests/compatibility/testcases/` directory.
    *   Each `.yaml` file defines a single test scenario, specifying the cty type, raw input data, and a descriptive name.

2.  **Data Generators:**
    *   `py_cty_generator.py`: A Python script that reads the YAML test cases, processes them using `pyvider.cty`, and generates:
        *   `py_type.json`: A JSON representation of the `pyvider.cty.CtyType`.
        *   `py_value.json`: A JSON representation of the resulting `pyvider.cty.CtyValue`.
    *   `go_cty_generator.go`: A Go program that reads the same YAML test cases, processes them using `go-cty`, and generates:
        *   `go_type.json`: A JSON representation of the `cty.Type`.
        *   `go_value.json`: A JSON representation of the resulting `cty.Value`.
    *   Both generators output these files into `tests/compatibility/output/<test_case_name>/`.
    *   The `*_value.json` files use a standardized format for representing cty values, including special handling for `unknown` and `null` values to allow for direct comparison.

3.  **Comparison Tool:**
    *   `compare_outputs.py`: A Python script that iterates through the output directories generated by the data generators.
    *   It compares `py_type.json` with `go_type.json`, and `py_value.json` with `go_value.json` for each test case.
    *   It reports any mismatches found, helping to pinpoint compatibility issues.

## Defining a New Test Case

To add a new test case:

1.  Create a new YAML file in the `tests/compatibility/testcases/` directory (e.g., `my_new_test.yaml`).
2.  Follow this structure:

    ```yaml
    name: MyNewTest # A unique name for the test case (used for output directory)
    description: "A brief description of what this test case covers."
    type_definition: "string"  # A string representing the cty type (e.g., "list(number)", "object({name=string,active=bool})")
    raw_input: "some data"     # The raw input data for the test.
                               # For null, use `null`.
                               # For unknown, use the special string `"__unknown__"`.
    # Example for a list of numbers:
    # type_definition: "list(number)"
    # raw_input:
    #   - 10
    #   - 20.5
    #   - 30
    ```

3.  The `type_definition` string should be parsable by both generators. Currently, basic types (`string`, `number`, `bool`) and simple lists (`list(typename)`) are supported in the POC. This may need to be expanded for more complex types.

## Running the Tests

1.  **Generate Data:**
    *   Ensure Go is installed and `go-cty` dependencies are available for the Go generator (refer to `go.mod` and `go.sum`).
    *   Run the Python generator:
        ```bash
        python tests/compatibility/py_cty_generator.py
        ```
    *   Run the Go generator:
        ```bash
        go run tests/compatibility/go_cty_generator.go
        ```
    *   These commands will populate the `tests/compatibility/output/` directory.

2.  **Compare Outputs:**
    *   Run the comparison tool:
        ```bash
        python tests/compatibility/compare_outputs.py
        ```
    *   The script will print the comparison results for each test case. If all files match, it will exit with code 0. If there are mismatches, it will print details of the first mismatch per file and exit with code 1.

## JSON Value Representation

To facilitate comparison, `*_value.json` files adhere to the following structure:

```json
{
  "type_name": "string", // Or "list(number)", "object({name=string})", etc.
  "value": "actual value here", // For collections, this will be a list/dict of recursively structured items. Null if unknown/null.
  "is_unknown": false,
  "is_null": false,
  "marks": [] // List of stringified marks
}
```

*   For `unknown` values: `"is_unknown": true`, `"value": null`.
*   For `null` values: `"is_null": true`, `"value": null`.
*   Numbers are represented as strings to maintain precision.
